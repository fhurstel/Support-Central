# Full-app review — 2026-07-16 (Fable)

Scope: React SPA (`frontend/`), PocketBase backend (`pocketbase/`, the deploy
target), FastAPI backend (`backend/`, reference implementation). Method: every
`frontend/src/services/api.js` call cross-checked against registered PocketBase
routes, plus FastAPI route semantics compared where behavior (not just shape)
matters.

## A. Functional gaps in the PocketBase compatibility layer

Ordered by user impact. "Frontend calls it" means a UI action hits the endpoint
today and currently fails (404/405) or silently no-ops on the PocketBase build.

1. **Voice & AI settings save is broken — method mismatch.**
   `updateVoiceAgentSettings` sends `POST /api/settings/voice-agent`; the layer
   registered only `PATCH`. Register POST (keep PATCH).
2. **Time entry edit/delete missing.** The ticket Time History edit pencil uses
   `PATCH /api/tickets/:id/time/:entryId` and `DELETE .../time/:entryId`.
   Neither exists. Implement both (update `started_at`/`ended_at`/
   `duration_seconds`/`description`; recompute nothing else).
3. **Lead workflow is incomplete — approval must convert.** FastAPI
   `review_lead` auto-creates a Ticket from an approved lead and sets
   `converted_ticket_id` (backend/app/api/routes/leads.py:110-135). The layer
   only flips status, so the Leads inbox "approve" does nothing useful. Also
   `POST /api/leads` (createLead) is missing entirely.
4. **Client members (contacts) are read-only.** `POST /api/clients/:id/members`,
   `PATCH`/`DELETE /api/clients/:id/members/:memberId` are missing — the
   Clients page contact modal can list but not add/edit/remove.
5. **Invoices cannot be created.** `POST /api/invoices` missing.
6. **Ticket members are a stub.** `POST /api/tickets/:id/members` and
   `DELETE /api/tickets/:id/members/:userId` are missing; `serTicket` returns
   `members: []` always. Add a `ticket_members` collection and wire both, plus
   the members array (and `member_ids_json`) in the serializer, with
   `added_member`/`removed_member` activity types.
7. **Ticket copy missing.** Modal "Copy" calls `POST /api/tickets/:id/copy`.
   Implement: duplicate ticket (new nid/ticket_number, " (copy)" title suffix),
   copying labels and checklists.
8. **Ticket delete.** The card modal Sidebar confirms then calls `onDelete`;
   verify what the parent (`Tickets.jsx`) invokes and wire the corresponding
   endpoint (likely `DELETE /api/tickets/:id`) end-to-end.
9. **Call log creation missing.** `POST /api/call-logs` (createCallLog).
   Implement minimally with a `call_logs` collection so the voice page can log.
10. **Kanban drag-and-drop does not persist.** `POST /api/board/reorder` is a
    no-op `{ok:true}`. Inspect the payload `reorderBoard` sends and persist
    status/position so board order survives refresh.
11. **No role enforcement / private-comment leak.** The layer has zero role
    checks: a GUEST login receives PRIVATE comments and can hit admin-ish
    mutations. Minimum: hide PRIVATE comments from GUEST in
    `GET /api/comments/ticket/:id`; restrict user-management and label/invoice/
    client/kb mutations to ADMIN/TECH.
12. **Poppy endpoints unregistered.** Optional integrations must fail
    gracefully (CLAUDE.md rule): register `/api/poppy/*` stubs returning empty
    data instead of PocketBase's native 404.

## B. Workflow improvements

- **Lead → ticket conversion (A3)** is the single biggest workflow win; it
  restores the intake funnel: lead arrives → review → approve → ticket appears
  on the board with the client attached.
- **Persisted kanban order (A10)** makes the board trustworthy for daily use.
- **Activity coverage:** log `created` on ticket create and `moved` when status
  changes via `PATCH /api/tickets/:id` (today only the /move endpoint logs).
- **Repeatable verification:** ad-hoc curl checks got us here; add
  `scripts/check-pocketbase.sh` that boots a fresh PB instance and asserts the
  whole API contract (auth, every entity CRUD touched above, persistence across
  restart) so future changes are provable in one command.

## C. Architecture / housekeeping

- Two backends now coexist. **PocketBase is the deployment target** (free
  hosting, single binary); **FastAPI remains the reference** for behavior
  parity. README should state this explicitly so contributors don't split
  effort.
- Keep the layer's conventions: integer `nid` exposed as `id`, foreign keys by
  nid, handlers in `pb_hooks/lib.js` (isolated-VM `require`), thin
  registrations in `pb_hooks/api.pb.js`, schema/seed via `pb_migrations/`.

## Verification bar for the fixes

Every item above lands only with: fresh-DB boot clean (migrations apply), the
new endpoint exercised via the API, and the affected UI flow driven in headless
Chromium against the real SPA with zero page errors — same bar used for the
existing features.
